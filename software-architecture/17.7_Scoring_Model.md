
# KELIA
# 17.7_Scoring_Model.md

**Version:** 1.0 (MVP)

---

# Purpose

This document defines how KELIA converts assessment responses into standardized scores and an overall compatibility percentage.

The MVP prioritizes simplicity, transparency and maintainability over algorithmic complexity.

---

# Step 1 – Calculate Raw Scores

Each response is assigned a numerical value:

| Response | Value |
|----------|------:|
| Strongly disagree | 1 |
| Disagree | 2 |
| Neutral | 3 |
| Agree | 4 |
| Strongly agree | 5 |

For reverse-scored questions, the values are inverted automatically.

---

# Step 2 – Calculate Assessment Scores

Each assessment produces:

- Raw score
- Normalized score (0–100)

Normalization Formula:

Normalized Score = ((Raw Score − Minimum Score) ÷ (Maximum Score − Minimum Score)) × 100

---

# Step 3 – Assessment Weights

For the MVP, each assessment contributes equally.

| Assessment | Weight |
|------------|-------:|
| Personality | 33.3% |
| Spiritual Compatibility | 33.3% |
| Relationship Compatibility | 33.3% |

Future versions may introduce dynamic weighting.

---

# Step 4 – Compatibility Calculation

For each assessment:

Difference = |User A Score − User B Score|

Compatibility = 100 − Difference

The overall compatibility score is the weighted average of the three assessment compatibility scores.

---

# Compatibility Interpretation

| Score | Interpretation |
|-------:|----------------|
| 90–100 | Excellent compatibility |
| 75–89 | Strong compatibility |
| 60–74 | Moderate compatibility |
| 45–59 | Limited compatibility |
| Below 45 | Significant differences |

These categories are informational only and must not discourage users from making their own decisions.

---

# Tie Handling

If two potential matches obtain identical scores:

Priority order:

1. Personality compatibility
2. Relationship compatibility
3. Spiritual compatibility
4. Most recently active member

---

# Stored Results

The database should store:

- Raw scores
- Normalized scores
- Overall compatibility score
- Compatibility category
- Calculation timestamp
- Scoring model version

---

# Design Principles

The scoring model must be:

- Explainable
- Reproducible
- Consistent
- Easy to improve in future releases

---

# Future Improvements (Excluded from MVP)

- Machine learning ranking
- Behavioral weighting
- Dynamic scoring
- AI-assisted compatibility analysis
