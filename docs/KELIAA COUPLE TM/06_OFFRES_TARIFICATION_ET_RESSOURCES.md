# 1. OBJET

Ce document définit l'architecture commerciale du Bilan Couple.

Il précise :

- les offres ;
- les prix ;
- la logique de valeur ;
- la réduction couple ;
- le contenu des rapports ;
- les différences entre les niveaux ;
- les ressources complémentaires ;
- les recommandations de sessions ;
- l'orientation vers des professionnels ;
- la logique de présentation commerciale ;
- les règles à respecter pour ne pas dévaloriser le produit.

Le principe central est simple :

> **Le couple achète une analyse complète de sa dynamique relationnelle, pas simplement un questionnaire.**

---

# 2. POSITIONNEMENT COMMERCIAL

Le Bilan Couple doit être positionné comme un **bilan relationnel approfondi**.

Il ne doit pas être présenté comme :

- un quiz amusant ;
- un test de personnalité ;
- un jeu de compatibilité ;
- une prédiction de mariage ;
- un diagnostic psychologique.

Positionnement recommandé :

> **Un bilan relationnel approfondi pour comprendre vos convergences, vos différences et les sujets que vous devez construire ensemble.**

---

# 3. PRINCIPLE DE TARIFICATION

Les prix doivent refléter :

- la profondeur du questionnaire ;
- l'analyse de deux profils ;
- le croisement des résultats ;
- la personnalisation ;
- la génération du rapport ;
- la qualité rédactionnelle ;
- la valeur des recommandations ;
- la possibilité d'utiliser le rapport comme outil de discussion.

Le prix doit donc être présenté comme le prix d'une **expérience d'analyse à deux**, et non comme le prix de deux questionnaires séparés.

# 9. POURQUOI LE PRIX COUPLE EST INFÉRIEUR À DEUX PRIX INDIVIDUELS

La réduction couple doit être présentée comme un avantage commercial logique.

Exemple :

> Le bilan est conçu pour fonctionner à deux. Au lieu de payer deux rapports séparés, vous bénéficiez d'un tarif couple qui inclut l'analyse croisée des deux profils.

Cela permet de valoriser :

- la collaboration ;
- le matching ;
- l'analyse commune.

La réduction ne doit pas donner l'impression que le produit est « bradé ».

# 17. RESSOURCES COMPLÉMENTAIRES

Le bilan peut orienter vers plusieurs catégories.

## Catégorie 1 — Ressources gratuites

Exemples :

- articles ;
- guides ;
- vidéos éducatives ;
- fiches pratiques ;
- questions de réflexion.

Objectif :

> permettre au couple de commencer à travailler seul.

---

# 18. CATÉGORIE 2 — SESSIONS

Selon le résultat, le système peut proposer :

- session communication ;
- session gestion des conflits ;
- session finances du couple ;
- session préparation au mariage ;
- session famille et belles-familles ;
- session parentalité ;
- session intimité et communication ;
- session projet de vie ;
- session rôles conjugaux.

Chaque recommandation doit être reliée au résultat.

---

# 19. CATÉGORIE 3 — PROGRAMMES

Lorsque plusieurs dimensions convergent vers un même besoin, le système peut proposer un programme plus complet.

Exemple :

```text
Communication faible
+
Conflits faibles
+
Écart de perception important
```

→ recommandation possible :

**Programme de communication et gestion des conflits**

---

# 20. CATÉGORIE 4 — ACCOMPAGNEMENT PROFESSIONNEL

Le système peut proposer une orientation vers :

- thérapeute de couple ;
- psychologue ;
- conseiller conjugal ;
- professionnel spécialisé dans le domaine concerné.

L'orientation doit rester informative.

Elle ne doit jamais être formulée comme :

> « Vous avez besoin d'une thérapie. »

Préférer :

> « Un accompagnement professionnel pourrait vous aider à approfondir ce sujet. »

---

# 21. RÈGLE D'ORIENTATION

La recommandation doit être proportionnée.

### Niveau faible

Ressource gratuite.

### Niveau modéré

Session ou guide.

### Niveau important

Accompagnement structuré.

### Situation sensible

Orientation vers un professionnel qualifié.

# 23. SYSTÈME DE RECOMMANDATION

Chaque ressource doit avoir un identifiant.

Exemple :

```text
RESOURCE_ID: RES-COM-001
CATEGORY: COMMUNICATION
TYPE: SESSION
TITLE: Communiquer sans se blesser
TARGET: COUPLE
PRIORITY: MODERATE
```

Le moteur pourra alors associer :

```text
RESULTAT
↓
RESOURCE_ID
↓
RECOMMANDATION
```

---

# 24. NE PAS SURVENDRE

Le rapport doit rester utile même si le client n'achète aucune ressource supplémentaire.

Le bilan ne doit jamais être conçu comme un simple tunnel de vente.

La recommandation commerciale doit apparaître comme :

> **Une possibilité d'aller plus loin.**

et non comme :

> **La solution obligatoire à votre résultat.**

---

## Vous souhaitez un accompagnement plus approfondi ?

Programmes.

## Vous traversez une situation complexe ?

# 26. OFFRE DE SESSION POST-BILAN

Une session peut être proposée directement depuis le rapport.

Exemple :

> **Votre résultat fait ressortir la gestion des conflits comme priorité.**
>
> Si vous souhaitez travailler ce sujet plus en profondeur, une session dédiée peut vous aider à construire une méthode commune de dialogue, de désescalade et de réparation.

Bouton :

**Découvrir la session**

---

# 27. LOGIQUE DE RECOMMANDATION MULTIPLE

Le système peut proposer plusieurs ressources, mais il ne doit pas créer une liste interminable.

Maximum recommandé :

- 3 ressources principales ;
- 2 ressources secondaires.

Priorité aux ressources les plus directement liées aux résultats.

---

# 28. RECOMMANDATION PERSONNALISÉE

Au lieu de :

> « Nous vous recommandons notre session communication. »

Préférer :

> « Votre bilan montre que votre communication quotidienne est plutôt solide, mais que vos perceptions divergent lorsque les sujets deviennent difficiles. Une session consacrée à la communication en situation de tension pourrait donc être particulièrement pertinente pour vous. »

---

# 30. RÈGLE DE PRIORITÉ COMMERCIALE

Le système doit recommander en priorité ce qui répond au besoin principal du couple.

Exemple :

Si les trois principaux résultats sont :

1. finances ;
2. conflits ;
3. famille ;

ne pas recommander d'abord une ressource générale sur l'estime de soi simplement parce qu'elle existe dans le catalogue.

---

# 31. RÈGLE DE COHÉRENCE

Toute recommandation affichée dans le rapport doit pouvoir être reliée à :

- une dimension ;
- une sous-dimension ;
- une règle d'interprétation ;
- un niveau de priorité.

Cela permet de garantir la cohérence du moteur.

---

# 32. COMMUNICATION DE LA RÉDUCTION

La réduction couple doit être visible sans devenir le principal argument.

Exemple :

> **Vous réalisez le bilan à deux et bénéficiez automatiquement du tarif couple.**

Puis :

**30 000 FCFA au lieu de 40 000 FCFA**

**10 000 FCFA économisés**

---

# 33. LOGIQUE DU CODE COUPLE

Le code couple ne doit pas être vendu séparément.

Il est généré lorsqu'un parcours de couple est créé.

Le premier utilisateur peut :

- acheter ;
- créer son espace ;
- obtenir son code ;
- inviter son partenaire.

Le deuxième partenaire peut :

- recevoir le lien ;
- saisir le code ;
- créer son propre compte ;
- compléter son questionnaire.

---

# 34. QUI PAIE ?

Peu importe lequel des partenaires paie.

Le système doit enregistrer :

```text
Couple_ID
Acheteur_ID
Offre
Montant
Date
Statut
```

Les droits de génération du rapport sont associés au couple.

---

# 35. CAS OÙ LE PREMIER PARTENAIRE NE PAIE PAS

Le système doit permettre :

```text
Création du couple
↓
Invitation du partenaire
↓
Questionnaires
↓
Paiement
↓
Génération du rapport
```

ou :

```text
Création du couple
↓
Paiement immédiat
↓
Invitation du partenaire
↓
Questionnaires
↓
Génération du rapport
```

Les deux parcours doivent être supportés.

---

# 36. CAS OÙ UN PARTENAIRE ABANDONNE

Le système doit conserver l'état du couple.

Exemple :

```text
Partenaire A : terminé
Partenaire B : 42 %
```

Le premier partenaire doit pouvoir revenir ultérieurement sans perdre ses données.

Le rapport final ne doit être généré qu'après satisfaction des conditions minimales de complétude.

---

# 37. CAS OÙ LE CODE EST DÉJÀ UTILISÉ

Si deux personnes sont déjà rattachées :

> Ce code de couple a déjà été utilisé. Chaque bilan est limité à deux partenaires.

Le système ne doit pas permettre l'ajout d'un troisième compte.

---

# 38. CAS DE DUPLICATION

Un même utilisateur ne doit pas pouvoir créer accidentellement plusieurs couples actifs pour le même bilan sans confirmation.

Le système peut afficher :

> Vous avez déjà un bilan couple en cours. Souhaitez-vous reprendre celui-ci ?

# 42. CE QU'IL NE FAUT PAS PROMETTRE

Ne jamais promettre :

- « savoir si vous êtes faits l'un pour l'autre » ;
- « savoir si votre mariage va réussir » ;
- « prédire votre avenir » ;
- « éliminer les conflits » ;
- « garantir votre mariage ».

---

# 43. PHRASES COMMERCIALES RECOMMANDÉES

> **Découvrez ce qui vous rapproche réellement.**

> **Identifiez les sujets qui méritent d'être clarifiés avant qu'ils ne deviennent des tensions.**

> **Comprenez votre dynamique de couple au-delà d'un simple pourcentage.**

> **Un bilan à deux, deux regards, une analyse commune.**

> **Votre différence n'est pas forcément un problème. Comprenez ce qu'elle signifie pour votre couple.**

---

# 44. GARANTIE DE VALEUR

Le client doit comprendre qu'il obtient :

```text
2 questionnaires
+
2 analyses individuelles
+
1 analyse croisée
+
1 rapport personnalisé
+
des recommandations
+
des ressources
```

Le produit doit donc être présenté comme une **analyse complète du couple**.

---

# 45. RÈGLE DE TRANSPARENCE

Le site doit expliquer clairement :

- le prix ;
- ce qui est inclus ;
- que les deux partenaires doivent répondre ;
- que les réponses sont individuelles ;
- que le rapport est généré après complétude ;
- que le score n'est pas un verdict ;
- que le bilan ne remplace pas une thérapie.

---

# 46. RÈGLE DE CONFIDENTIALITÉ COMMERCIALE

La communication ne doit jamais utiliser les réponses personnelles d'un partenaire comme argument contre lui.

Exemple interdit :

> « Votre partenaire vous voit comme… »

Préférer :

> « Votre rapport de couple met en évidence un écart de perception concernant… »

---

# 47. RÈGLE D'UPSELL

L'upsell doit se produire principalement **après la valeur délivrée**.

Le rapport doit d'abord aider.

Ensuite :

> « Si vous souhaitez travailler davantage ce sujet, voici une ressource adaptée à votre résultat. »

# 53. PRINCIPLE DIRECTEUR

La stratégie commerciale doit respecter une règle :

> **Ne jamais vendre la peur créée par le résultat. Vendre la valeur créée par la compréhension.**

Le couple ne doit pas acheter parce qu'il a peur d'être « incompatible ».

Il doit acheter parce qu'il veut :

- mieux se comprendre ;
- préparer son mariage ;
- clarifier ses attentes ;
- renforcer ses bases ;
- prévenir certains malentendus ;
- apprendre à travailler ensemble.
