# KELYA COUPLE™

## Parcours écran par écran --- UX, onboarding, états, textes et comportements

**Document maître de conception de l'expérience utilisateur**

------------------------------------------------------------------------

# 1. OBJECTIF DU DOCUMENT

Ce document décrit **l'expérience vécue par l'utilisateur**, écran par
écran, depuis la découverte de KELYA COUPLE jusqu'à la consultation du
rapport.

Il complète le document d'architecture produit.

Le Document 02 répond principalement à :

> « Comment le produit fonctionne-t-il ? »

Le présent document répond à :

> **« Qu'est-ce que l'utilisateur voit, comprend, ressent et fait à
> chaque étape ? »**

Chaque écran doit être pensé comme une étape d'un parcours cohérent.

L'utilisateur ne doit jamais se demander :

> « Qu'est-ce que je dois faire maintenant ? »

Le système doit toujours lui montrer la prochaine action.

------------------------------------------------------------------------

# 2. PRINCIPES UX NON NÉGOCIABLES

L'expérience KELYA COUPLE repose sur sept principes.

## 2.1 CLARTÉ

Une seule action principale doit ressortir à chaque étape.

## 2.2 RASSURANCE

Le couple doit comprendre que le bilan n'est pas un jugement.

## 2.3 VALORISATION

L'achat doit être accueilli comme une décision positive.

## 2.4 PROGRESSION

Le parcours doit être visible.

## 2.5 INDIVIDUALITÉ

Chaque partenaire répond de son côté.

## 2.6 CONSTRUCTION À DEUX

Le résultat final concerne la dynamique du couple.

## 2.7 PREMIUM

Chaque écran doit donner l'impression d'un service réfléchi, élégant et
qualitatif.

# 11. ÉCRAN 08 --- FAQ AVANT ACHAT

Questions recommandées :

### Est-ce que le prix est pour deux personnes ?

Oui. Un achat couvre les deux partenaires.

### Faut-il que nous soyons mariés ?

Non. Le bilan peut être réalisé par des couples, des fiancés et des
partenaires souhaitant mieux comprendre leur dynamique.

### Mon partenaire doit-il être membre de KELYA ?

Non.

### Peut-il répondre de son côté ?

Oui. C'est même le fonctionnement prévu.

### Est-ce que mon partenaire verra mes réponses ?

Les réponses individuelles restent protégées.

### Le bilan nous dira-t-il si nous sommes compatibles ?

Il donne une analyse structurée de votre dynamique. Il ne décide pas à
votre place de l'avenir de votre relation.

-   cohérentes ;
-   accessibles ;
-   désactivables si nécessaire ;
-   adaptées au mobile.

Éviter les animations excessives.

Le produit doit rester premium.

------------------------------------------------------------------------

# 62. SYSTÈME DE PROGRESSION

Le système doit afficher un état clair.

Exemple :

``` text
MON PARCOURS

✓ Achat
✓ Espace couple
✓ Mon questionnaire
● Invitation partenaire
○ Analyse
○ Rapport
```

Le partenaire peut avoir une progression séparée.

------------------------------------------------------------------------

# 63. DOUBLE PROGRESSION

Lorsque les deux partenaires sont connectés :

``` text
VOTRE PROGRESSION

Thomas       ✓ 100 %
Sarah        ● 62 %

ANALYSE DU COUPLE

○ En attente des deux questionnaires
```

Lorsque les deux terminent :

``` text
Thomas       ✓ 100 %
Sarah        ✓ 100 %

ANALYSE DU COUPLE

● En préparation
```

------------------------------------------------------------------------

# 64. ÉTAT DE CHARGEMENT

Pendant les traitements, éviter une animation vide.

Afficher un texte expliquant ce qui se passe.

Exemple :

> **Nous réunissons vos deux profils.**

> Nous analysons vos convergences, vos différences et les domaines qui
> méritent votre attention.

Cela rend l'attente utile et rassurante.

------------------------------------------------------------------------

# 65. RAPPORT EN PLUSIEURS NIVEAUX

L'interface doit pouvoir distinguer :

### Résumé

Lecture rapide.

### Analyse complète

Lecture approfondie.

### Exercices

Travail pratique.

### Plan d'action

Mise en application.

### Ressources

Pour aller plus loin.

Cette architecture fonctionne pour les deux niveaux d'offre.

------------------------------------------------------------------------

# 66. PREMIUM PLUS DANS L'INTERFACE

Lorsque l'utilisateur a acheté Premium Plus, l'interface doit révéler
naturellement les éléments supplémentaires.

Exemple :

> **Votre espace Premium Plus**

Puis :

-   simulations ;
-   protocoles ;
-   outils avancés ;
-   plan d'action 12 semaines ;
-   charte conjugale ;
-   évaluations approfondies.

Ne pas cacher le Premium Plus derrière un simple badge.

Il doit se ressentir dans la profondeur de l'expérience.

------------------------------------------------------------------------

# 67. ESSENTIEL DANS L'INTERFACE

L'offre Essentiel doit rester riche.

Il ne faut jamais donner l'impression :

> « Vous avez pris la version moins chère donc vous avez presque rien. »

L'Essentiel doit être présenté comme un véritable bilan complet.

Le Premium Plus ajoute de la profondeur, pas la qualité minimale.

------------------------------------------------------------------------

# 68. RÈGLE DE VENTE APRÈS ACHAT

Ne pas proposer immédiatement une montée en gamme agressive.

Si une offre supérieure est disponible après achat, elle doit être
présentée avec prudence et uniquement lorsque cela est pertinent.

La priorité reste :

> **faire réussir l'utilisateur dans le service qu'il a acheté.**

------------------------------------------------------------------------

# 69. RESPONSIVE

Sur mobile :

-   navigation simplifiée ;
-   cartes empilées ;
-   boutons pleine largeur si pertinent ;
-   texte lisible ;
-   progression visible ;
-   espaces d'écriture adaptés.

Sur desktop :

-   davantage de largeur ;
-   panneaux côte à côte ;
-   visualisations plus riches.

Le contenu reste identique.

------------------------------------------------------------------------

# 70. ACCESSIBILITÉ

Prévoir :

-   contraste suffisant ;
-   tailles de texte lisibles ;
-   navigation clavier ;
-   textes alternatifs ;
-   réduction des animations ;
-   messages d'erreur compréhensibles ;
-   états visuels qui ne reposent pas uniquement sur la couleur.

------------------------------------------------------------------------

# 71. TON DES MICRO-COPIES

Les textes courts de l'interface doivent rester humains.

Éviter :

> « Process completed. »

Préférer :

> **Votre étape est terminée.**

Éviter :

> « Waiting for participant B. »

Préférer :

> **Nous attendons maintenant la partie de votre partenaire.**

Éviter :

> « Report generated. »

Préférer :

> **Votre bilan est prêt.**

------------------------------------------------------------------------

# 72. RÈGLE SUR LE PARTENAIRE

Ne jamais présenter le partenaire comme un obstacle.

Éviter :

> « Votre partenaire n'a toujours pas répondu. »

Préférer :

> **Votre partenaire n'a pas encore terminé son questionnaire.**

Puis proposer :

> **Renvoyer l'invitation**

Le langage doit préserver la relation.

------------------------------------------------------------------------

# 73. RÈGLE SUR L'ATTENTE

L'attente doit être présentée comme une étape normale.

Exemple :

> **Votre partie est terminée.**

> Lorsque votre partenaire aura terminé, votre analyse pourra commencer.

Cela évite que l'utilisateur pense que le système est bloqué.

------------------------------------------------------------------------

# 74. RÈGLE DE CONTINUITÉ

Chaque écran doit reprendre visuellement :

-   le logo KELYA ;
-   la couleur ;
-   la typographie ;
-   les composants ;
-   la navigation cohérente.

KELYA COUPLE peut avoir des illustrations spécifiques mais doit rester
immédiatement reconnaissable comme KELYA.

# 78. ÉTAT VIDE

Aucun écran ne doit être vide.

Si aucun rapport n'est disponible :

> **Votre analyse apparaîtra ici lorsque vos deux questionnaires seront
> terminés.**

Si aucune ressource n'est encore disponible :

> **Vos recommandations personnalisées apparaîtront ici après votre
> analyse.**

------------------------------------------------------------------------

# 79. ÉCRAN DE FERMETURE DE SESSION

Lorsque l'utilisateur quitte :

> **À bientôt. Votre progression est enregistrée.**

Cela rassure particulièrement lors du questionnaire.

------------------------------------------------------------------------

# 80. RÈGLE DE COHÉRENCE DU PARCOURS

Le système doit toujours respecter :

``` text
Une action
↓
Une confirmation
↓
Une prochaine étape
```

Exemple :

``` text
Questionnaire terminé
↓
Confirmation
↓
Inviter le partenaire
```

Puis :

``` text
Partenaire terminé
↓
Confirmation
↓
Analyse en préparation
```

Puis :

``` text
Rapport prêt
↓
Confirmation
↓
Découvrir le bilan
```
