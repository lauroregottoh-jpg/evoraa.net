# 181. MOTEUR DE DÉCISION — KELIAA COUPLE™

Le moteur KELIAA COUPLE™ doit fonctionner selon une logique de décision progressive.

Il ne doit pas simplement chercher les scores les plus élevés ou les plus faibles.

Pour chaque domaine, il doit déterminer :

**1. Ce que les deux personnes ont en commun.**

**2. Ce qui les différencie.**

**3. L'importance de cette différence.**

**4. La manière dont cette différence peut se manifester.**

**5. Si cette différence constitue une force, une complémentarité, une zone à clarifier ou une priorité de travail.**

**6. Quelle ressource est la plus adaptée.**

Cette logique doit être appliquée à chaque domaine pertinent.

---

# 182. HIÉRARCHIE DES INFORMATIONS

Lorsque plusieurs informations sont disponibles, le moteur doit les traiter dans cet ordre :

### Niveau 1 — Réponses individuelles

Ce que chaque personne a répondu.

### Niveau 2 — Scores individuels

Les tendances qui ressortent des réponses.

### Niveau 3 — Comparaison

Les écarts et convergences entre les deux profils.

### Niveau 4 — Importance relationnelle

La manière dont ces écarts peuvent influencer la vie à deux.

### Niveau 5 — Contexte

La situation du couple : intérêt, cheminement, fiançailles, mariage récent ou mariage établi.

### Niveau 6 — Priorisation

Ce qui mérite réellement d'être approfondi.

### Niveau 7 — Ressources

Les outils à proposer.

Cette hiérarchie évite que le moteur saute directement du score à une recommandation.

---

# 183. MATRICE DE LECTURE D'UNE DIMENSION

Pour chaque grande dimension, le moteur doit pouvoir construire en interne une fiche de lecture.

### DIMENSION

Exemple : finances.

### PARTENAIRE A

Tendance principale.

### PARTENAIRE B

Tendance principale.

### ÉCART

Faible / modéré / important.

### CONVERGENCE

Faible / modérée / forte.

### SIGNIFICATION POSSIBLE

Ce que l'écart peut représenter.

### IMPACT POTENTIEL

Faible / modéré / important.

### TYPE

Force / complémentarité / clarification / vigilance / priorité.

### RESSOURCE

Carte / exercice / fiche / protocole.

### NIVEAU D'OFFRE

Essentiel / Premium / Premium Plus.

Cette structure est une donnée interne du moteur.

Elle ne doit pas être affichée comme une fiche technique dans le rapport final.

---

# 184. LE MOTEUR DOIT DISTINGUER « DIFFÉRENCE » ET « PROBLÈME »

C'est une règle fondamentale.

Une différence n'est pas automatiquement un problème.

Exemple :

L'un aime planifier.

L'autre préfère improviser.

Le moteur ne doit pas conclure :

> « Vous avez un problème d'organisation. »

Il doit plutôt analyser :

> « Votre rapport au planning semble différent. Cette différence peut être légère dans votre quotidien, mais elle peut devenir plus visible lorsque vous devez organiser un voyage, gérer un budget ou prendre une décision importante. »

Puis déterminer si une ressource est réellement nécessaire.

---

# 185. DISTINGUER « CONVERGENCE » ET « ABSENCE DE PROBLÈME »

Une convergence ne signifie pas que tout est réglé.

Exemple :

Deux personnes veulent toutes les deux avoir des enfants.

Cela indique une convergence sur l'objectif.

Mais elles peuvent différer sur :

- le moment ;
- le nombre ;
- l'éducation ;
- la répartition des responsabilités ;
- la place des familles ;
- la discipline ;
- les valeurs transmises.

Le moteur doit donc parfois approfondir une convergence importante pour identifier les nuances derrière celle-ci.

---

# 186. LES CONVERGENCES PEUVENT DONNER LIEU À DES EXERCICES

Un exercice ne doit pas être réservé aux difficultés.

Exemple :

> « Vous partagez une vision très proche de votre futur foyer. Prenez maintenant quelques minutes pour transformer cette vision commune en cinq principes concrets que vous souhaitez réellement vivre au quotidien. »

La ressource devient alors un outil de consolidation.

---

# 187. LES FORCES DOIVENT ÊTRE TRANSFORMÉES EN RESSOURCES

Lorsqu'une force importante apparaît, le moteur peut proposer :

- une fiche de consolidation ;
- une carte de gratitude ;
- une activité de projection ;
- une charte de couple ;
- un exercice de préservation ;
- un rituel hebdomadaire ;
- une activité de reconnexion.

Ainsi, les forces ne sont pas seulement décrites.

Elles deviennent quelque chose que le couple peut entretenir.

---

# 188. SYSTÈME DE « ZONE VERTE / ORANGE / ROUGE »

Si une représentation visuelle est utilisée, elle doit être expliquée avec prudence.

### ZONE VERTE

Une dimension qui apparaît comme une ressource ou une base solide.

### ZONE ORANGE

Une dimension qui mérite une conversation ou une attention particulière.

### ZONE ROUGE

Une dimension présentant un écart ou une difficulté suffisamment importante pour justifier un travail structuré.

Cette représentation ne doit jamais être interprétée comme :

**vert = bon couple**

**rouge = mauvais couple.**

Elle décrit uniquement le niveau d'attention recommandé pour une dimension.

---

# 189. NE PAS AFFICHER TROP DE COULEURS

Le design doit rester élégant.

Éviter une interface ressemblant à un tableau de contrôle.

Les couleurs doivent servir à hiérarchiser l'information, pas à dramatiser.

---

# 190. SYSTÈME DE « NIVEAU D'ATTENTION »

Une alternative plus douce peut être utilisée :

### À PRÉSERVER

Une force.

### À EXPLORER

Un sujet intéressant.

### À CLARIFIER

Une différence qui mérite une conversation.

### À TRAVAILLER

Une priorité.

Ce vocabulaire est plus cohérent avec l'identité de KELIAA.

---

# 191. GÉNÉRATION DE LA SYNTHÈSE

Avant de rédiger le rapport complet, le moteur doit générer une synthèse interne.

Cette synthèse doit contenir :

### Trois forces majeures

### Trois convergences importantes

### Trois différences importantes

### Trois priorités éventuelles

### Une phrase décrivant la dynamique générale

### Les ressources recommandées

### Les ressources Premium Plus supplémentaires, si applicables

Cette synthèse sert ensuite de colonne vertébrale au rapport.

---

# 192. NE PAS DÉPASSER LE NOMBRE DE PRIORITÉS UTILES

Le moteur doit éviter de produire quinze priorités.

Recommandation :

**3 priorités principales maximum** dans la synthèse.

Si quatre domaines sont importants, le quatrième peut apparaître dans les analyses sans devenir une priorité centrale.

---

# 193. RÈGLE DES « TROIS CHOSES »

Lorsque cela est possible, privilégier :

- 3 forces ;
- 3 différences ;
- 3 priorités ;
- 3 actions immédiates.

Trois éléments sont plus faciles à retenir qu'une longue liste.

Cette règle n'est pas absolue.

Elle peut être dépassée lorsque les résultats nécessitent davantage de profondeur.

---

# 194. GÉNÉRATION DE LA CONCLUSION À PARTIR DES DONNÉES

La conclusion ne doit pas être écrite indépendamment du rapport.

Elle doit être générée à partir de la synthèse interne.

Elle doit reprendre :

**ce qui est solide**

+

**ce qui demande de l'attention**

+

**ce que le couple peut faire maintenant.**

Elle doit également rappeler que le bilan est un outil de compréhension et non une prédiction.

---

# 195. RÈGLE DE COHÉRENCE ENTRE TITRE ET CONTENU

Un titre doit annoncer exactement ce qui suit.

Éviter un titre spectaculaire pour un contenu banal.

Exemple :

> **« Ce qui peut changer votre couple »**

si la section ne présente qu'une analyse statistique.

Préférer :

> **« Ce que vos différences peuvent changer dans votre quotidien »**

si la section explique effectivement les conséquences possibles.

---

# 196. RÈGLE DES SOUS-TITRES

Les sous-titres doivent aider le lecteur à naviguer.

Privilégier :

- **Ce qui vous rapproche**
- **Là où vos attentes diffèrent**
- **Ce que cette différence peut produire**
- **Ce que vous pouvez en faire**
- **Votre première action**

Éviter les titres trop techniques :

- Dimension 1 ;
- Variable A ;
- Analyse B ;
- Score C.

---

# 197. TITRES ORIENTÉS LECTEUR

Lorsque cela améliore la lecture, utiliser des titres qui parlent directement au couple.

Exemples :

> **Ce que vous semblez déjà bien construire ensemble**

> **Là où vos deux fonctionnements se rencontrent**

> **Le sujet que vous avez intérêt à clarifier**

> **Ce que vous pouvez commencer à faire cette semaine**

Ces titres rendent le rapport plus humain.

---

# 198. RÈGLE DES ENCADRÉS

Les encadrés peuvent être utilisés pour les informations essentielles.

Exemples :

### À RETENIR

Une idée importante.

### VOTRE POINT FORT

Une convergence.

### VOTRE POINT D'ATTENTION

Une différence.

### VOTRE PROCHAINE ÉTAPE

Une action.

### À DISCUTER À DEUX

Une question.

Les encadrés ne doivent pas être utilisés à chaque paragraphe.

---

# 199. RÈGLE DES PHRASES FORTES

Certaines pages peuvent contenir une phrase forte mise en évidence.

Exemple :

> **Vous ne cherchez pas nécessairement la même chose de la même manière. Et c'est précisément ce que votre couple doit apprendre à comprendre.**

Ou :

> **Votre vision est commune. Votre manière d'y arriver ne l'est pas toujours.**

Ces phrases doivent être produites à partir des résultats et non ajoutées artificiellement pour faire joli.

---

# 200. EXERCICES — GÉNÉRATION DYNAMIQUE

Le moteur ne doit pas simplement copier un exercice de la bibliothèque.

Il doit pouvoir adapter :

- l'introduction ;
- les exemples ;
- les questions ;
- le nombre de questions ;
- la durée ;
- le niveau de difficulté ;
- le débrief ;
- l'action finale.

Exemple :

La bibliothèque contient :

**« Notre vision financière »**

Mais le rapport peut produire :

> « Vos réponses montrent que la sécurité financière n'a pas exactement le même sens pour vous deux. Nous vous proposons donc de ne pas commencer par parler de budget. Commencez plutôt par répondre séparément aux quatre questions suivantes... »

Puis les questions sont adaptées à leur situation.

---

# 201. NE PAS ALTÉRER LE FOND MÉTHODOLOGIQUE

La personnalisation ne doit pas dénaturer l'exercice.

Le moteur peut adapter la formulation.

Il ne doit pas modifier arbitrairement :

- l'objectif ;
- la logique ;
- la sécurité ;
- les étapes essentielles.

---

# 202. RÈGLE DES EXEMPLES

Lorsque des exemples sont utilisés, ils doivent être clairement présentés comme exemples.

Exemple :

> « Par exemple, une différence sur la gestion de l'argent peut apparaître lorsqu'un partenaire souhaite épargner une somme importante tandis que l'autre préfère l'utiliser pour un projet immédiat. »

Ne jamais faire passer un exemple pour une information réellement fournie par le couple.

---

# 203. RÈGLE DE PERSONNALISATION DES EXEMPLES

Lorsque les données permettent de choisir un exemple pertinent, le moteur doit privilégier celui qui correspond au domaine concerné.

Exemple :

Si la priorité est la famille :

→ utiliser un exemple lié aux familles.

Si la priorité est la communication :

→ utiliser un exemple de conversation.

Si la priorité est financière :

→ utiliser un exemple financier.

---

# 204. GÉNÉRATION DES RECOMMANDATIONS

Chaque recommandation doit comporter implicitement :

**quoi faire**

**quand**

**avec qui**

**combien de temps**

**comment savoir si cela a aidé**

Exemple :

> « Cette semaine, choisissez un moment de trente minutes pour parler uniquement de la place des familles dans votre futur foyer. Chacun écrit auparavant ses trois limites principales. Pendant la conversation, votre objectif n'est pas de parvenir immédiatement à un accord, mais d'identifier les points sur lesquels vous êtes déjà alignés et ceux qui nécessitent encore une discussion. »

---

# 205. RECOMMANDATIONS INDIVIDUELLES

Certaines recommandations doivent être destinées à une seule personne.

Exemple :

> « De votre côté, votre premier travail peut consister à exprimer plus clairement ce que vous ressentez avant d'attendre que votre partenaire le devine. Lorsque vous avez besoin de réassurance, essayez de formuler directement votre besoin plutôt que de tester indirectement la réaction de l'autre. »

Toujours éviter le ton accusateur.

---

# 206. RECOMMANDATIONS POUR LE COUPLE

D'autres recommandations doivent être formulées au « vous ».

Exemple :

> « Votre priorité commune est de créer une manière plus prévisible de gérer les désaccords. Commencez par définir ensemble ce qui vous permet de faire une pause sans interrompre définitivement la conversation. »

---

# 207. PLANS D'ACTION À PLUSIEURS NIVEAUX

Le moteur peut générer :

### ACTION IMMÉDIATE

Une action de moins de 30 minutes.

### ACTION COURT TERME

Une action sur 7 jours.

### ACTION MOYEN TERME

Une action sur 21 jours ou plusieurs semaines.

### ACTION DE CONSOLIDATION

Une habitude à maintenir.

Cette structure est particulièrement adaptée au Premium Plus.

---

# 208. PREMIUM — PLAN D'ACTION

Le Premium peut généralement proposer :

**1 priorité principale**

+

**2 ou 3 actions concrètes**

+

**2 à 5 ressources ciblées**

+

**un outil de suivi simple.**

Le couple doit pouvoir commencer sans se sentir submergé.

---

# 209. PREMIUM PLUS — PLAN D'ACTION

Premium Plus peut proposer :

**3 priorités maximum**

+

**actions immédiates**

+

**plan sur 7 jours**

+

**plan sur 21 jours lorsque pertinent**

+

**protocoles**

+

**outils de suivi**

+

**engagements du couple**

+

**ressources supplémentaires.**

---

# 210. RÈGLE DU PLAN D'ACTION « RÉALISTE »

Le moteur doit prendre en compte la vie du couple.

Éviter les plans irréalistes.

Un couple qui travaille beaucoup, a des enfants ou traverse une période chargée ne doit pas recevoir le même rythme qu'un couple qui dispose de beaucoup de temps.

Si le contexte n'est pas connu, proposer un rythme raisonnable et adaptable.

---

# 211. RÈGLE DE SUIVI PREMIUM PLUS

Lorsque Premium Plus propose un parcours, chaque étape doit avoir une fonction.

Exemple :

### SEMAINE 1

Comprendre.

### SEMAINE 2

Communiquer.

### SEMAINE 3

Pratiquer.

### SEMAINE 4

Ajuster.

Ne pas créer un calendrier artificiel simplement pour donner l'impression de profondeur.

---

# 212. RAPPORT ET RESSOURCES : NE PAS DUPLIQUER

Si une explication complète figure dans le rapport, la fiche téléchargeable peut être plus pratique.

Elle ne doit pas recopier mot pour mot dix pages du rapport.

Le rapport explique.

La fiche fait pratiquer.

La carte fait discuter.

Le protocole fait progresser.

---

# 213. RÈGLE DE COMPLÉMENTARITÉ DES FORMATS

### RAPPORT

Comprendre.

### CARTE

Déclencher une conversation.

### FICHE

Réfléchir et écrire.

### EXERCICE

Pratiquer.

### PROTOCOLE

Progresser sur plusieurs étapes.

### SUIVI

Observer l'évolution.

Cette distinction doit guider toute la bibliothèque.

---

# 214. RÈGLE DE CONCEPTION DES CARTES

Chaque carte doit être suffisamment courte pour être lue en quelques secondes.

Structure :

**Titre**

Une question ou une consigne.

**Temps estimé**

Éventuellement.

**Comment l'utiliser**

Une phrase.

**Espace de réponse**

Si nécessaire.

---

# 215. RÈGLE DE CONCEPTION DES FICHES

Une fiche peut être plus longue.

Elle doit toutefois rester centrée sur un seul objectif.

Une fiche ne doit pas chercher à traiter :

communication + finances + famille + intimité

simultanément.

**Une fiche = un objectif principal.**

---

# 216. RÈGLE DE CONCEPTION DES PROTOCOLES

Un protocole peut traiter un sujet complexe.

Mais il doit être divisé en étapes.

Chaque étape doit préciser :

- objectif ;
- durée ;
- consigne ;
- exercice ;
- résultat attendu ;
- transition vers l'étape suivante.

---

# 217. RÈGLE DE CONCEPTION DES JOURNAUX

Un journal doit être réutilisable.

Éviter de créer un journal qui ne peut être rempli qu'une seule fois.

Prévoir des pages répétables.

Exemple :

**Notre point de la semaine**

Cette page peut être utilisée chaque semaine.

---

# 218. RÈGLE DE CONCEPTION DES OUTILS IMPRIMABLES

Chaque outil imprimable doit être autonome.

Une personne qui imprime uniquement la fiche doit comprendre :

- ce qu'elle fait ;
- pourquoi ;
- comment ;
- quoi remplir ;
- quoi faire ensuite.

Elle ne doit pas avoir besoin de relire tout le rapport pour comprendre l'exercice.

---

# 219. RÈGLE DE CONCEPTION DES OUTILS INTERACTIFS

Lorsque l'outil est intégré à KELIAA :

- les champs doivent être suffisamment grands ;
- les réponses doivent être sauvegardées ;
- l'utilisateur doit savoir s'il a terminé ;
- il doit pouvoir revenir modifier ses réponses lorsque prévu ;
- il doit pouvoir exporter ou télécharger lorsqu'une telle fonctionnalité est disponible.

Ne jamais afficher une fonctionnalité qui n'existe pas techniquement.

---

# 220. RÈGLE DE NOMMAGE DES RESSOURCES

Les noms doivent être simples et évocateurs.

Préférer :

**Notre vision financière**

plutôt que :

**Fiche exercice FIN-04.**

Préférer :

**Notre manière de gérer les désaccords**

plutôt que :

**Protocole COM-02.**

Les codes peuvent exister en interne, mais ils ne doivent pas être visibles par défaut.

---

# 221. IDENTIFIANTS INTERNES

Chaque ressource doit néanmoins posséder un identifiant interne unique.

Exemple :

`COUPLE-COM-001`

`COUPLE-CONFLIT-004`

`COUPLE-FIN-002`

`COUPLE-MARIAGE-006`

Ces identifiants servent au moteur, aux développeurs et à la maintenance.

---

# 222. VERSIONNAGE DES RESSOURCES

Les ressources doivent pouvoir évoluer sans casser les anciens rapports.

Prévoir :

**version 1.0**

**version 1.1**

**version 2.0**

Lorsqu'une ressource est améliorée, le système doit conserver la traçabilité de la version utilisée dans un rapport déjà généré.

---

# 223. RÈGLE DE NON-MODIFICATION DES RAPPORTS LIVRÉS

Une ressource peut être améliorée pour les nouveaux rapports.

Mais un rapport déjà livré ne doit pas changer silencieusement.

Le couple doit conserver la version qui lui a été fournie.

---

# 224. BIBLIOTHÈQUE MAÎTRE

Tous les contenus doivent être centralisés dans une bibliothèque maître.

Cette bibliothèque constitue la source de référence.

Elle contient :

- exercices ;
- cartes ;
- fiches ;
- protocoles ;
- recommandations ;
- phrases de transition ;
- règles de personnalisation ;
- règles de sélection.

Le moteur doit s'appuyer sur cette bibliothèque plutôt que d'inventer continuellement de nouveaux contenus.

---

# 225. CRÉATION DYNAMIQUE : AUTORISÉE MAIS ENCADRÉE

Le moteur peut créer une formulation personnalisée lorsqu'aucune ressource existante ne correspond parfaitement.

Mais il doit respecter :

- les principes méthodologiques ;
- le ton KELIAA ;
- la structure ;
- les règles anti-IA ;
- la sécurité ;
- le niveau d'offre.

Il ne doit pas inventer une nouvelle méthode psychologique simplement parce qu'un profil est inhabituel.

---

# 226. RÈGLE DE PRIORITÉ DE LA BIBLIOTHÈQUE

Lorsqu'une ressource pertinente existe :

**UTILISER LA RESSOURCE EXISTANTE.**

Lorsqu'elle existe mais nécessite une adaptation :

**ADAPTER LA RESSOURCE EXISTANTE.**

Lorsqu'aucune ressource n'existe :

**GÉNÉRER UNE RESSOURCE NOUVELLE À PARTIR DES RÈGLES KELIAA.**

Cette règle permet de maintenir une cohérence méthodologique.

---

# 227. CONTRÔLE DES NOUVELLES RESSOURCES

Une nouvelle ressource créée automatiquement ne doit pas être ajoutée définitivement à la bibliothèque maître sans validation.

Elle peut être classée :

**PROPOSITION À VALIDER**

avant intégration.

Cela évite que le moteur enrichisse indéfiniment la bibliothèque avec des contenus incohérents.

---

# 228. OBJECTIF : UNE BIBLIOTHÈQUE RICHE MAIS MAÎTRISÉE

Le but n'est pas de posséder des milliers de ressources.

Le but est d'avoir :

**suffisamment de ressources pour couvrir les situations importantes,**

**suffisamment de variété pour éviter les répétitions,**

**suffisamment de profondeur pour Premium Plus,**

et **une architecture suffisamment claire pour que le moteur sache quoi utiliser.**

---

# 229. RÈGLE DE MAINTENANCE

Chaque nouvelle ressource doit être évaluée selon quatre critères :

### UTILITÉ

Est-elle réellement utile ?

### DIFFÉRENCIATION

Apporte-t-elle quelque chose qui n'existe pas déjà ?

### QUALITÉ

Est-elle suffisamment bien rédigée ?

### RÉUTILISABILITÉ

Peut-elle être adaptée à plusieurs profils ?

Si elle échoue sur plusieurs critères, elle ne doit pas être ajoutée.

---

# 230. TEST DE LA BIBLIOTHÈQUE

Avant lancement, tester le moteur avec plusieurs profils fictifs.

Minimum recommandé :

### CAS 1

Couple très convergent.

### CAS 2

Couple très différent mais complémentaire.

### CAS 3

Couple avec conflit de communication.

### CAS 4

Couple avec divergence financière.

### CAS 5

Couple préparant son mariage.

### CAS 6

Couple marié depuis plusieurs années.

### CAS 7

Couple présentant plusieurs zones de vigilance.

### CAS 8

Couple avec une excellente dynamique globale mais une seule priorité forte.

### CAS 9

Couple avec des réponses très asymétriques.

### CAS 10

Couple Premium Plus nécessitant plusieurs protocoles.

Ces cas servent à vérifier que le moteur ne produit pas dix rapports quasiment identiques.

---

# 231. TEST DE VARIATION

Pour un même cas fictif, générer plusieurs rapports si nécessaire.

Vérifier :

- les formulations ;
- les exercices ;
- les cartes ;
- les transitions ;
- les exemples.

La structure doit rester cohérente mais le texte ne doit pas sembler copié-collé.

---

# 232. TEST DE COHÉRENCE PREMIUM

Prendre un même couple fictif.

Générer :

**Premium**

puis :

**Premium Plus.**

Comparer.

Le Premium Plus doit contenir :

**100 % du Premium**

+

**les approfondissements Premium Plus.**

Il ne doit pas supprimer une analyse importante présente dans le Premium.

---

# 233. TEST DE VALEUR PREMIUM PLUS

Après génération du Premium Plus, poser la question :

> « Qu'est-ce que le couple reçoit ici qu'il n'aurait pas reçu avec Premium ? »

La réponse doit être claire.

Exemples :

- analyse plus profonde ;
- protocole ;
- suivi ;
- scénarios ;
- ressources supplémentaires ;
- conversations guidées ;
- charte ;
- parcours.

Si la différence n'est pas perceptible, le Premium Plus doit être retravaillé.

---

# 234. TEST DE LECTURE HUMAINE

Faire lire le rapport à une personne qui n'a pas participé à sa création.

Lui demander :

> « Est-ce que ce rapport semble avoir été écrit pour ce couple ? »

> « Est-ce que tu comprends ce que le couple doit faire ? »

> « Est-ce que les exercices sont suffisamment clairs ? »

> « Est-ce que tu trouves le texte naturel ? »

> « Est-ce que tu comprends la différence entre Premium et Premium Plus ? »

Ces retours doivent servir à améliorer le moteur.

# 236. PRINCIPE DE CONCEPTION FINAL

KELIAA COUPLE™ doit être conçu comme un **système cohérent**, pas comme une collection de textes.

Le test produit les données.

Les données produisent une lecture.

La lecture produit des priorités.

Les priorités déclenchent des ressources.

Les ressources produisent des conversations.

Les conversations produisent des actions.

Les actions peuvent être suivies.

C'est cette chaîne qui constitue l'expérience KELIAA.

---

# 237. FORMULE INTERNE DU MOTEUR

La logique générale peut être résumée ainsi :

**RÉPONSES**

↓

# 238. DERNIÈRE RÈGLE POUR CURSOR

Ne jamais demander au système :

> « Génère un beau rapport de couple. »

Cette instruction est trop vague.

Le système doit disposer de la totalité des règles précédentes et comprendre que la génération se fait en plusieurs étapes.

La logique attendue est :

**1. Lire les données.**

**2. Construire la carte interne du couple.**

**3. Identifier les convergences.**

**4. Identifier les différences.**

**5. Classer les différences.**

**6. Déterminer les priorités.**

**7. Sélectionner les ressources.**

**8. Construire l'analyse.**

**9. Construire les exercices.**

**10. Construire les recommandations.**

**11. Construire le plan d'action.**

**12. Construire la conclusion.**

**13. Vérifier l'offre Premium ou Premium Plus.**

**14. Vérifier la cohérence globale.**

**15. Appliquer la charte rédactionnelle.**

**16. Appliquer la mise en forme.**

**17. Effectuer le contrôle qualité.**

**18. Générer le rapport final.**

# 239. RÈGLE ABSOLUE DE NON-IMPROVISATION

Lorsque le moteur ne dispose pas d'une information, il ne doit pas l'inventer.

Lorsque le test ne permet pas de conclure, il doit le dire.

Lorsque deux interprétations sont possibles, il doit présenter la possibilité avec prudence.

Lorsque les données sont insuffisantes pour proposer une recommandation personnalisée, il doit utiliser une ressource générale appropriée plutôt que fabriquer une situation.

**La personnalisation doit être profonde, mais toujours fondée sur les données disponibles.**

---

# 240. RÈGLE ABSOLUE DE QUALITÉ

Avant de considérer une génération comme terminée, le moteur doit vérifier une dernière fois :

> **« Est-ce que ce contenu aide réellement ces deux personnes à mieux comprendre leur relation et à savoir quoi faire ensuite ? »**

Si oui, conserver.

Si non, réécrire.

Si le contenu est seulement joli mais inutile, supprimer.

Si le contenu est intelligent mais trop abstrait, concrétiser.

Si le contenu est utile mais trop froid, humaniser.

Si le contenu est chaleureux mais trop vague, le rendre plus direct.

Si le contenu est long mais répétitif, le réduire.

Si le contenu est court parce qu'il manque de profondeur, l'enrichir.

**La qualité KELIAA repose sur cet équilibre.**
